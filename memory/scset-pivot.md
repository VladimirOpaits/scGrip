2026-07-02. User wants to stop the expensive per-cell Geneformer + double-Harmony validation loop and use **scSet** ([github.com/clinicalml/scset](https://github.com/clinicalml/scset), bioRxiv 2025.08.21.671613): a diffusion-autoencoder that maps a patient's **set of cells → one vector**. Chosen path = **full scSet on Census scVI latents** (not Geneformer), because pretraining needs many patients and Census ships precomputed scVI for free, whereas Geneformer would need re-embedding hundreds of patients on the 6GB GPU. Caveat accepted: scVI **explicitly models out batch** (assay/dataset/donor) so the [[first-validation-result]] "technology dominates" premise may vanish in scVI space — re-validate later.

**Ruler caution (2026-07-04):** when comparing substrates on batch-dominance, use the SAME ruler. The Geneformer "13×" is CENTROID (pbmcsca; centroid overstates — bigger dataset went 39× centroid). The honest distribution ruler ([[mmd-distribution-ruler]]) brought Geneformer to **~6.4× (MMD)**. Our scVI/scSet **2.44× is centroid**, so it is comparable to Geneformer's centroid (~13×/39×), NOT to its MMD 6.4×. Apples-to-apples requires computing MMD-dominance for scVI too (not yet done). Implication: the "scVI compressed the signal" worry is likely MILDER than 13×→2.44× suggested; the held-out failure is better explained by the diagnosis≈dataset confound in the baseline (see [[enrichment-heldout-result]]) than by substrate.

**Architecture (ported into repo, self-contained, smoke-tested):** `scset_model.py` (ABMIL + CellTransformer encoders → model_dim=256; ConditionalDenoisingMLP w/ AdaLN ResidualBlocks; cosine DDPM). Pretrain = self-supervised: encode patient's **anchor** cells → embedding, condition a DDPM to denoise held-out **target** cells of same patient (`scset_pretrain.py`, cell_transformer, num_target=16, steps_per_sample=8, T=1000, lr1e-3, clip0.1). `scset_embed.py` extracts one 256-d vector per patient. Their original harness is broken (imports missing train_* modules) — only the core modules are usable.

**Census scVI pull — hard-won method (`corpus_pull.py`, `scvi_pull.py`):** scVI IS available in census 2025-11-08 (our download version) as contrib embedding CxG-czi-15; uri = `s3://cellxgene-contrib-public` + relative_uri from `get_all_available_embeddings`. Fetch via `tiledbsoma.open(uri)` + `E.read(coords=...)`, NOT `ex.get_embedding()` (re-opens census every call) and NOT `get_anndata(obs_embeddings=["scvi"])` for big sets (loads ALL matching cells → **OOM at ~7GB on the 14GB laptop**, silent kill). Winning pattern: obs metadata-only scan once → `data/scvi_corpus/obs.parquet` (lung/primary/3-assays, 3.9M cells, 587 patients); then **per-patient contiguous range-read** `E.read(coords=(slice(lo,hi),))` on a single open array, write one `.npy` per patient (resumable, tiny RAM, visible progress). Value-filter scans cost ~13min each (full 159M-row obs) so avoid per-dataset loops. Corpus = 576 patients ≥200 cells (cap 800/patient, 50-dim); **downstream adeno/normal now 109 adeno / 272 normal across 3 techs** — far more power than the old 43. Pull ordered adeno→normal→rest, ~7h unattended (systemd-inhibit holds sleep). Data: `data/scvi_corpus/cells/*.npy` + `meta.csv` (pid, technology=assay, disease, dataset_id, donor_id, n_cells).

Next when pull done: pretrain encoder → embed patients → reuse [[lancedb-platform]] selection.py + held-out design on scSet vectors. Related: [[quantile-sweet-spot-result]], [[pivot-to-diagnosis-data]].
