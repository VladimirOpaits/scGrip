Gap-to-ceiling (quantile, auc@0->auc@20): Chen 0.77->0.89 (ceil 0.84), Lee 0.56->0.95 (ceil 0.95, HITS ceiling), Uhlitz 0.90->1.00 (0.99), MUI 0.85->0.98 (1.00), Zhang 0.60->0.85 (0.73). **macro 0.74->0.94, closed +0.20; negctrl flat 0.54->0.49 in every study.** Enrichment closes the gap in ALL 5 studies (unlike Census's mixed picture), several reaching their within-study ceiling = diversity cohort transfers to an unseen study as well as a within-study classifier. Confirms the effect is substrate-agnostic. Caveat unchanged: quantile>=random>farthest only marginally (closed 0.20/0.18/0.18) — "diversity helps" is strong, "our selector beats random" still only directional. Baselines here are NOT <0.5 (CRC pool less batch-confounded than Census lung). Results: `crc_enrichment_results.csv`.

**HARDER-TASK TEST — MSI-vs-MSS among tumors (`scripts/crc_msi.py`, `data/crc/msi_labels.parquet`), the answer to "is it just easy cancer-vs-normal?":** reuses per-sample signatures (no new PCA). 353 labeled tumors (114 MSI/239 MSS); held-out = Joanito/Chen/Borras, base 10x3'v3, N=10/10, K=15. MSI is genuinely HARD: within-study ceilings Chen 0.70, Borras 0.69 (Joanito 0.98). Result (macro, ceiling 0.79): baseline k=0 = 0.51 (chance — MSI does NOT transfer homogeneously), enriched auc@K quantile 0.64 / **farthest 0.68** / random 0.64, negctrl flat 0.50->0.51. **CONCLUSION: the de-confounding effect SURVIVES a subtle molecular label (0.51->~0.66, negctrl flat) — so it is NOT an artifact of tumor-vs-normal being easy. BUT it's much more modest and does NOT reach ceiling (0.66 vs 0.79) — the dramatic "hits ceiling" in tumor-vs-normal WAS partly task-easiness (user was right).** Also: on this hard task the SELECTOR beats random more clearly than anywhere else (Chen: random -0.01 vs quantile/farthest +0.08/+0.12; farthest best macro) — targeted diversity matters when the signal is subtle. Caveat: small n (pool 37 MSI), noisy; Joanito ceiling 0.98 vs transfer 0.70 = strong-but-untransferable within-study MSI signal. Overall "too good" verdict: PCA leakage ruled out; task-easiness inflated the magnitude but the effect itself is real on a hard label.

**scSet vs RFF-MMD HEAD-TO-HEAD (2026-07-05, `scripts/scset_crc.py` -> `data/crc/signatures_scset.parquet`):** scSet pretrained on the SAME shared PCA-50 cells, POOL-ONLY (359 train/39 val, 5 held-out studies excluded from the encoder = leak-free), 256-dim per sample, val loss 0.86->0.43. Fed the SAME `crc_enrichment.py` / `crc_msi.py` via CRC_SIG env. Compare by ENDPOINT (auc@k = best achievable transfer; NOT "closed" which is inflated by a worse baseline). **tumor-vs-normal: TIE** — scSet macro 0.59->0.93 vs RFF-MMD 0.74->0.94; identical endpoint (~0.93-0.94, both saturate the 0.90 ceiling), but scSet's k=0 baseline is LOWER (0.59 vs 0.74) = its learned encoder is MORE batch-entangled (it must encode batch-specific expression to reconstruct cells; fixed RFF kernel is more neutral). **MSI (hard) — RFF-MMD WINS:** scSet macro 0.54->0.62 (closed +0.07-0.09) vs RFF-MMD 0.51->0.66 (+0.13-0.17); scSet works on only 1/3 studies (Joanito 0.48->0.76; Chen & Borras ~0 closed). **VERDICT: at single-atlas scale (~400 training patients) scSet does NOT beat RFF-MMD — tie on easy, slightly worse on hard. Confirms the data-budget prediction: the learned encoder needs more data than one atlas to amortize capacity; parameter-free wins/ties for free & reproducibly. scSet's edge is a platform-scale (multi-atlas) hypothesis, untestable on the 4050.** Strong "simple baseline suffices" result for the paper.

**ADD experiment (2026-07-05, `scripts/crc_add.py` -> `crc_add_results.csv`) — the cleanest diversity-vs-volume separation, and the REALISTIC use case (add data, not replace).** Prompted by user: we only ever did fixed-size REPLACE (which controls volume implicitly); never tested ADD (grow cohort), which is the actual product scenario, and never controlled WHICH patients get removed. ADD design: fixed seed cohort (15+15 from base 10x5'v1), then ADD up to k=15/class (cohort 30->60), 50 seeds. Arms: diverse (quantile/farthest from other techs), random (other techs), **homogeneous (MORE of base tech = pure volume, zero diversity)**, negctrl. Result (macro, ceiling 0.90, auc@0=0.76 for all): **quantile +0.16 (->0.92), farthest +0.15, random +0.14 (->0.90), homogeneous (pure volume) -0.02 (->0.74), negctrl flat +0.04.** DECISIVE: **adding more SAME-tech data does nothing / slightly HURTS (-0.02, doubling down on the confounded axis); adding equal-volume DIVERSE data drives transfer to the ceiling (+~0.15). The ~0.18 gap between diverse-add and homogeneous-add is purely diversity, not volume.** This kills the "it's just more data" explanation more cleanly than REPLACE did (here volume is an explicit control arm). Realistic scenario (add) works, with the caveat that the added data must be diverse. Caveat: homogeneous-add capped by base-tech pool (30 samples). quantile≈farthest≈random again. This is a paper-central figure. (The "which patients removed" question is moot in ADD since nothing is removed.)

**FULL DISTRIBUTIONS + MSI-ADD (2026-07-05) — calibration of the selector claim.** Looking at per-seed distributions (not just rounded means): (1) **diversity>volume is statistically ironclad** — quantile−homogeneous paired @endpoint: tumor/normal +0.181, min +0.11, **100% of seeds**, non-overlapping distributions; MSI-ADD (`crc_add_msi.py`, N=8/8 K=8, thin data) +0.061, **86% of seeds** (weaker because on the hard task homogeneous-add helps a bit too, 0.52->0.58 — less batch-confound headroom). (2) **selector (quantile/farthest) vs random is NOT significant on mean/endpoint ANYWHERE** — tumor/normal: quantile−random +0.015 (56%), pooled diverse−random +0.012 (**48%**, coin flip); MSI-ADD: quantile−random +0.006 (50%), farthest−random −0.010 (38%). The earlier "MSI hints selector matters on hard tasks" was WITHIN this noise — retracted. (3) **The only reproducible edge of smart selection is SAMPLE-EFFICIENCY + VARIANCE-REDUCTION, not a higher ceiling:** farthest reaches near-ceiling by k=5-7 vs random's k=10-15; and farthest's downside is tight (tumor/normal @k=15: farthest min 0.892, never <0.89; random min 0.770, 12% of seeds <0.85). **Paper framing: main claim = diversity>volume (decisive); retrieval-vs-random = active-learning-style efficiency/reliability gain in low budget, NOT asymptotic mean lift.** Results: `crc_add_results.csv`, `crc_add_msi_results.csv`.

**LEAVE-ONE-STUDY-OUT robustness (2026-07-05, `scripts/crc_loso.py`) — answering "why only those 5 held-out studies?"** Held out EACH paired study alone (pool = all others; auto-pick base tech), diverse-add vs homogeneous-add, 30 seeds, over the 8 paired studies with minority>=10. **Direction is ROBUST: diverse >= homogeneous in ALL 8 (never worse, worst −0.01); clear win (+0.05..+0.13) in 5/8 (Joanito +0.13, Lee +0.10, MUI +0.06, Li +0.05, Uhlitz +0.02), tie in 3/8 (Chen, Wu, Zhang ~−0.01); negctrl flat ~0.5 everywhere.** BUT magnitude is NOT robust — where diverse≈homo, homogeneous-add ALSO helps (rich pool + already-decent baseline leaves little pure-confound to exploit). **Important caveat this exposes: the headline ADD result (+0.16 diverse, −0.02 homogeneous, 100% seeds) was partly an artifact of holding out all 5 balanced studies AT ONCE, which depletes the pool of well-paired data and makes homogeneous-add look harmful. Single-holdout (LOSO, richer pool) is more conservative but still positive.** Paper: report BOTH — 5-at-once as the vivid contrast, LOSO as honest robustness ("directionally robust, magnitude depends on how well the baseline already transfers"). NOT leave-one-study-out CV in the headline; the main experiment uses a fixed 5-study held-out set chosen for pairing+balance while leaving a healthy pool.

**QUANTILE DEFAULT UPDATED q=0.75 -> q=0.90 (2026-07-05).** A fresh q-sweep on CRC-ADD (`scripts/crc_qsweep.py`, q in [0.5,0.65,0.75,0.9,1.0]) showed the endpoint is flat for q>=0.65 (~0.90-0.92) but higher q gives better speed (auc@k5: 0.84->0.90 as q 0.5->1.0) and reliability (frac<0.85: 12%->0%, min 0.68->0.89) monotonically toward farthest. q=0.75 (the old Census-era sweet spot) was mildly conservative for CRC; **q=0.90 chosen as the new default** — near-farthest speed/reliability without committing to pure farthest (which can chase pathological outliers on datasets with weird outlier techs, as seen in the earlier Census/Harmony phase where farthest was WORST). IMPORTANT CORRECTION: farthest has TIGHTER distribution than quantile at the endpoint (farthest sd 0.01, min 0.892, 0% frac<0.85 vs quantile-0.75 sd 0.02, min 0.840, 2% frac<0.85) — quantile is not "less dispersed", it's a safer middle ground. All QUANT constants updated to 0.90 across crc_enrichment.py, crc_msi.py, crc_add.py, crc_add_msi.py, crc_loso.py; reran — results barely move (macro replace 0.74->0.93 vs 0.94 before; ADD +0.16 unchanged; MSI closed 0.13->0.15, slightly better).
